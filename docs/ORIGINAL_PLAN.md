# AE 库存监测仪表盘：实施与交接计划

## 一、目标、版本与项目组织

### 1. 产品目标

开发一个适用于齿轮盛宴 v0.4.8.18 的服务端 Mod，内置只读网页，持续记录 AE 库存，提供数量趋势、净变化量、净变化速率、收藏、筛选和 NBT 合并查看。

**数据存储采用 SQLite。** 不要求安装外部数据库、Node.js 服务或其他常驻进程；网页静态资源随服务端 JAR 分发。

日常使用仅安装服务端 Mod。客户端导出器作为独立工具，用于生成与玩家客户端一致的中文名称和图标资源包，不参与日常库存采集。

### 2. 已确定的产品决策

| 项目       | 决定                                                     |
| ---------- | -------------------------------------------------------- |
| 网络范围   | 只监测有 AE 控制器的网络                                 |
| 发现方式   | 自动发现已加载网络，保留曾发现网络的历史；不强制加载区块 |
| 统计含义   | 库存数量、净变化、净变化速率，不宣称生产量或消耗量       |
| 采样周期   | 默认每 10 秒                                             |
| 历史精度   | 10 秒保留 24 小时；1 分钟保留 7 天；15 分钟保留 30 天    |
| 存储限制   | 历史数据及数据库辅助文件合计预算默认 2 GiB               |
| 容量不足   | 优先清理最旧历史，实际保留时间可以短于 30 天             |
| 访问方式   | 默认 `0.0.0.0:18766`，自动生成主密码；可配置公开访问     |
| 网页权限   | 只读；不提供游戏操作、管理配置或资源上传接口             |
| 浏览器设置 | 收藏、别名、筛选、布局、时间范围等仅保存在浏览器         |
| NBT 合并   | 默认关闭；开启后按资源类型及注册 ID 合并所有 NBT 变体    |
| 多项对比   | 同一网络最多对比 6 项；不同单位分图                      |
| 资源包分发 | 管理员手动放到服务端指定目录                             |
| 界面方向   | 深色、克制的工业仪表盘，蓝灰底色、少量琥珀色强调         |

## 二、服务端采集、网络身份与统计规则

### 1. 运行结构

```text
AE 网络
  ↓ Minecraft 主线程读取
不可变库存快照
  ├─ 原子发布 → HTTP 当前库存查询
  └─ 有界队列 → 单写入线程 → SQLite 历史与降采样
                                  ↑
                           有界历史查询线程
```

职责必须明确：

- 主线程负责 AE 对象、库存缓存及网络状态读取。
- 序列化、SQLite、压缩和 HTTP 响应不在主线程执行。
- HTTP 线程不得直接访问 AE 网络或 Minecraft 世界对象。
- 浏览器刷新不会触发额外 AE 扫描。
- 后台线程只能接收脱离游戏对象的不可变数据。
- 队列满时丢弃整份未入库采样并登记缺口，不阻塞游戏、不写入半份库存。
- 后台执行器、请求队列和查询缓存都有容量限制。

AE2 `15.4.10` 的 `IStorageService#getCachedInventory()` 返回共享缓存，官方建议在容许稍旧数据时优先使用；不得修改返回对象，也不得为了监测调用 `invalidateCache()`。[官方源码](https://raw.githubusercontent.com/AppliedEnergistics/Applied-Energistics-2/forge/v15.4.10/src/main/java/appeng/api/networking/storage/IStorageService.java)

### 2. 网络发现

通过官方 `GridServices.register(...)` 注册轻量监测服务，利用节点加入、离开及 tick 回调维护活动网络。

- 只把包含控制器的网络加入监测目录。
- 控制器多方块只对应一条网络记录。
- 同一个 AE 网络跨维度连接时仍是一条记录。
- 无控制器子网络不单独展示。
- 主网络通过存储总线看到的库存，按 AE 实际提供的库存视图统计。
- 不全世界扫描，不读取未加载区块，不设置区块加载票。
- 不因断电、控制器冲突或区块卸载删除历史网络。
- 节点变更回调只记录变更，待网络更新完成后再解析状态；避免读取正在重组的网络。

优先使用公开 API。控制器识别涉及具体实现类时集中在 AE2 适配层，覆盖原版控制器及实际附属 Mod 的相关实现；不在业务代码散布类型判断或反射。

### 3. 持久网络身份

不能使用 Java 对象地址、运行期序号或控制器坐标字符串直接作为永久网络 ID。

采用：

- 每个存档独立 `worldId`。
- 每个历史网络独立随机 UUID。
- 以控制器的“维度 ID＋方块坐标集合”作为重识别依据。
- 网络目录、控制器锚点和历史关系存入 SQLite。

匹配规则：

1. 控制器集合未变或存在唯一明确重叠时，恢复已有网络 UUID。
2. 拆分时，按控制器重叠数量分配旧身份；同一旧身份最多给一个分支。
3. 合并时，保留重叠最多的旧身份，其余记录为合并来源。
4. 平局按历史创建时间、UUID、控制器排序确定，不能依赖回调顺序。
5. 无重叠时分配新 UUID，不猜测它是否是搬迁后的旧网络。
6. 所有身份冲突统一批处理，避免同一轮内两个网络抢占同一身份。

检测到拆分、合并、重建或不可用后恢复时，开始新的连续统计段。**不同段之间不计算速率**，避免拓扑变化制造虚假的生产或消耗尖峰。

网页显示自动名称、维度、代表坐标和状态；用户自定义网络别名仅保存在本地浏览器。

### 4. 采样语义

- 默认每 10 秒安排一次采样，时间以真实经过时间衡量。
- TPS 降低时不补跑一串历史采样，也不假设每次一定相隔 10 秒。
- 每份快照记录真实采样时间、网络 UUID、连续段 ID 和完整性。
- 网络间错峰采样，避免全部集中在同一个 tick。
- 同一网络的一份快照必须完整读取后再发布；不把跨多个 tick 的部分库存拼成同一时刻。
- 只采集实际存储资源，不把仅存在合成配方的条目当作库存。
- 以前存在、本次完整快照消失的条目，数量记为零。
- 采样失败、网络失效或未加载时记为未知，不能记为零。

断电、重组、控制器冲突、卸载、采样错误和过期快照应有不同内部状态；网页使用简短中文状态显示。

### 5. 资源身份与单位

精确身份包含 AE 类型及完整持久化 NBT，使用提取后的共享身份算法：

- 服务端和客户端导出器调用同一 `contracts` 模块。
- 固定身份协议版本，提供黄金测试向量。
- NBT 复合标签键排序不影响身份，列表顺序及数值类型仍影响身份。
- 数量不参与身份。
- 哈希身份冲突或不一致必须报错隔离，不能静默合并。

物品单位为“个”；此 Forge 版本的流体原始单位为 mB，`1000 mB = 1 B`。其他 AE 资源类型保留类型标识和单位信息；无法正确解析的类型显示“不支持”，不能误标成物品。

数量在 API 中使用十进制字符串。Java 端合并计算使用 `BigInteger`，浏览器使用 `BigInt`，不通过 JavaScript `Number` 中转精确库存。

### 6. NBT 合并与统计

合并键为：

```text
AE 资源类型 + 注册 ID
```

开启合并时，药水效果、附魔、耐久、自定义名称等全部 NBT 差异被忽略。分组可以展开查看精确变体。

每次完整采样同时计算：

- 精确资源序列。
- 同注册 ID 合并序列。

两类序列独立记录和降采样。不能用各变体已经降采样后的最大值相加来构造合并最大值。

统计定义：

- 数量：对应观测时刻的库存。
- 净变化：连续有效区间末值减初值。
- 平均净速率：净变化除以两端真实观测时间差，默认显示每分钟。
- 图上速率：相邻有效观测点的净变化除以真实时间差。
- 至少两个有效时间点才显示速率。
- 发生缺口或连续段切换时断线，不跨缺口计算速率。
- 区间不完整时显示覆盖情况，不把部分区间统计伪装成完整区间结果。

外部抽屉、箱子、存储盘挂载变化也可能改变库存，因此所有文案统一使用“净变化”，不使用“产量”。

## 三、SQLite 实现、保留策略与 HTTP 接口

### 1. 数据库位置和基本配置

数据库放在当前世界保存目录下的 `ae2-dashboard/history.sqlite`，避免不同存档共用历史。

使用 SQLite JDBC，驱动及所需运行依赖随服务端 JAR 打包，验证 Linux 与 Windows 加载。用户不需要另装 SQLite。

默认：

- WAL 模式。
- `synchronous=NORMAL`。
- 单写入线程。
- 最多两个历史读取连接。
- 短事务，批量预编译写入。
- 写入事务不等待网页请求。
- 查询完成后立即结束事务，不能在向慢客户端发送响应时占用读事务。

WAL 允许读取与写入并行，但长时间读事务会妨碍检查点回收，因此查询超时和连接释放必须实现。[SQLite WAL 文档](https://www.sqlite.org/wal.html)

正常停服排空有界队列并执行检查点，最多等待 5 秒；崩溃时允许丢失尚未提交的末尾采样，不能丢失已经提交的历史。

### 2. 逻辑表结构

| 数据                 | 保存内容                                        |
| -------------------- | ----------------------------------------------- |
| `meta`               | 数据库版本、存档 UUID、身份协议版本             |
| `networks`           | 网络 UUID、首次／最后发现时间、最后状态         |
| `controller_anchors` | 网络与控制器维度、坐标的映射                    |
| `network_events`     | 拆分、合并、失效、恢复及关联网络                |
| `resources`          | 精确资源 ID、类型、注册 ID、序列化身份和分组 ID |
| `series`             | 网络与精确／合并资源的序列关系                  |
| `sample_frames`      | 完整采样时间、连续段、采集和持久化状态          |
| `raw_changes`        | 原始数量变化点，包括归零记录                    |
| `rollup_1m`          | 1 分钟聚合记录                                  |
| `rollup_15m`         | 15 分钟聚合记录                                 |

数量使用精确整数表示；需要超过 64 位的字段使用十进制文本，不能依赖 SQLite 浮点运算计算库存。

索引围绕“网络＋序列＋时间”建立，另为按时间清理建立索引。网页趋势查询不得扫描全库。

### 3. 不按固定周期重复保存全部库存

采用**变化点＋完整采样时间记录＋边界基线**：

- 每次完整采样保存一条采样时间记录。
- 资源数量变化时才写数量记录。
- 新资源、归零、连续段起点必须写入。
- 数量不变时，不反复写入相同数量。
- 聚合层对完全平稳、连续有效的时间段也避免重复记录。
- 查询平稳区间时，从边界基线恢复数量，再结合完整采样记录确认覆盖。
- 缺口、段切换或未完成采样阻断延续，禁止无限向前填充。
- 清理旧数据前保留新边界所需基线；基线只用于重建状态，不作为保留区间内的观测点。

这能让大量长期不变的物品只占少量存储，同时保留“确实采样过但没有变化”和“没有采样”的区别。

### 4. 降采样

| 层级   |     最细粒度 | 最长保留 |
| ------ | -----------: | -------: |
| 原始层 | 实际约 10 秒 |  24 小时 |
| 分钟层 |       1 分钟 |     7 天 |
| 长期层 |      15 分钟 |    30 天 |

每个有变化的桶保存：

- 桶边界及连续段。
- 首尾有效时间和数量。
- 最小、最大数量。
- 有效采样数量和完整性信息。

按 UTC 对齐桶。1 分钟聚合从原始采样生成，15 分钟聚合从已提交的分钟聚合生成；任务幂等，可在崩溃后重跑。

删除较细数据前，必须确认对应粗粒度结果已提交。

默认曲线显示桶末值，悬浮提示显示真实时间和区间极值。提供“波动范围”显示选项，不能把降采样后的曲线宣传成原始全部采样点。

跨越多个保留层级的查询，使用覆盖整个请求范围的可用粒度，不在同一条线上偷偷混用不同精度。

### 5. 容量限制与异常处理

历史目录默认总预算为 2 GiB：

- 主数据库上限设为 1792 MiB。
- 其余预算用于 WAL、辅助文件和维护余量。
- 资源图标包独立管理，默认最多 512 MiB，不计入历史数据库预算。
- 每分钟及较大写入批次前检查占用。
- 达到历史预算 85% 时启动提前清理，目标回落到 75%。
- 清理顺序为最旧历史时间段，连同无引用的旧资源目录记录一并处理。
- SQLite 已分配但空闲的页面优先重用；清理后文件未立即缩小不应误判为仍然满。
- 不在运行中执行需要复制整个数据库的全量 `VACUUM`。
- 限制维护事务大小、读取时长和 WAL 增长，并安排检查点。
- `journal_size_limit` 不能视为 WAL 任意时刻的硬上限。[SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)

触及预算、磁盘空间不足或无法回收 WAL 时：

1. 停止新增历史写入。
2. 保留当前内存库存监测。
3. 记录明确状态和历史缺口。
4. 网页显示“历史记录暂停”及简短原因。
5. 空间恢复后自动尝试继续，使用新的连续段。

不得循环吞异常、阻塞主线程，或悄悄返回残缺库存。

数据库损坏时保留原文件，不自动覆盖。未知较新数据库版本拒绝写入；版本迁移在事务中执行，迁移失败不得破坏原数据库。

### 6. HTTP、密码与只读边界

使用 JDK `HttpServer`，同端口提供静态网页和 `/api/v1`。

默认配置：

```text
bindAddress = "0.0.0.0"
port = 18766
authMode = "password"
sampleIntervalSeconds = 10
historyBudgetMiB = 2048
```

首次启动生成 32 字节随机密码，使用 Base64URL 编码写入 Mod 配置文件：

- 不在网页、API 响应或日志中打印密码。
- 配置文件已存在密码时不覆盖。
- 密码模式下空密码触发生成，不能隐式切换公开模式。
- 公开访问必须显式配置 `authMode = "public"`。
- 改密码和访问模式重启后生效。
- 主密码授予全部监测网络的只读访问；第一版不做账号和逐网络权限。

登录使用 POST，返回随机会话 Cookie：

- `HttpOnly`、`SameSite=Strict`。
- HTTPS 部署时设置 `Secure`。
- 会话保存在内存，重启失效；闲置 1 小时或最长 12 小时失效。
- 浏览器不保存主密码。
- 登录有有界速率限制，避免限流记录本身无限增长。
- CORS 默认关闭，登录和退出校验同源。
- 静态页面可以匿名加载，但库存、历史和资源映射遵循配置的认证模式。

登录和退出仅修改认证会话，不属于游戏写入功能。其余业务接口只提供 GET／HEAD，不实现合成、取出、注册账号、改配置或上传资源包。

默认监听 HTTP；部署文档明确外网密码访问通过 HTTPS 反向代理提供。实际开放端口、调整防火墙及部署另行进行。

### 7. API 契约

| 接口                                  | 用途                                         |
| ------------------------------------- | -------------------------------------------- |
| `GET /api/v1/status`                  | 认证模式、登录状态；登录后包含采样及存储状态 |
| `POST /api/v1/session`                | 主密码登录                                   |
| `DELETE /api/v1/session`              | 退出会话                                     |
| `GET /api/v1/networks`                | 网络目录、状态、最后观测时间                 |
| `GET /api/v1/networks/{id}/inventory` | 当前或明确标注的最后库存                     |
| `GET /api/v1/networks/{id}/history`   | 最多 6 项的数量、速率及覆盖信息              |
| `GET /api/v1/networks/{id}/events`    | 网络状态与拓扑事件                           |
| `GET /api/v1/resources`               | 资源元数据和名称映射，支持分页               |
| `GET /api/v1/assets/manifest`         | 当前名称／图标包版本                         |
| `GET /api/v1/assets/{hash}.png`       | 已校验图标资源                               |

统一要求：

- 时间使用 UTC，界面转换为浏览器时区。
- 返回 `worldId`、网络 ID、采样时间及快照版本。
- 数量和精确差值使用十进制字符串。
- 历史响应明确返回实际粒度、有效范围、缺口和是否被保留策略截断。
- 单条趋势最多 1200 个显示桶。
- 过细的手动粒度返回明确参数错误和建议粒度；自动模式可选更粗粒度。
- 分页、返回字节数、并发查询及查询时间均有限制。
- 不向浏览器返回数据库路径、堆栈或完整原始 NBT。
- 请求取消和页面切换后，过期结果不能覆盖当前网络的数据。
- 端口占用仅使网页不可用，采样和历史记录继续运行并记录错误。

## 四、客户端导出器与网页体验

### 1. 客户端导出流程

提取旧名称导出器后，新增命令：

```text
/ae2dashboardassets sample
/ae2dashboardassets export
/ae2dashboardassets cancel
```

默认输出到客户端游戏目录的 `ae2-dashboard-assets/`。

采集来源：

- 物品注册表默认实例。
- 创造模式展示和搜索条目的变体。
- 玩家背包中的实例副本。
- 流体注册表及可识别容器中的流体。
- 管理员提供的“服务器已发现资源身份清单”。

服务端提供仅管理员可用的本地／控制台导出命令，把已发现精确资源身份写为清单文件。管理员手动将文件放到客户端工具输入目录，用于补齐注册表无法枚举的 NBT 变体。网页不暴露原始 NBT 导出接口。

客户端工具只处理本地文件和对象副本，不自动连接监测 API、不发送操作包、不修改物品或世界。

### 2. 名称和图标

- 中文名称使用当前客户端真实显示名称，包含适用的资源包与脚本改名。
- 物品图标通过 Minecraft 客户端实际渲染器生成。
- 流体图标使用实际纹理与颜色信息。
- 输出透明背景 64×64 PNG，打包为有边距的图集。
- 采用静态快照，不承诺复现动态动画或所有随时间变化的自定义渲染。
- 使用真实精确资源身份绑定名称和图标。
- 未覆盖变体显示服务器名称或注册 ID 与占位图，不能冒用其他变体结果。
- 合并组使用基础资源名称和基础图标，并显示变体数量。

客户端渲染必须在正确渲染线程执行。每帧增量处理，后台只接收脱离游戏对象的像素和字符串。

切换世界、语言或资源包时取消当前导出；恢复所有渲染状态，释放离屏缓冲。单个资源失败可记录跳过，渲染环境或内存错误则中止整个导出。

### 3. 资源包协议

资源包包含：

- 格式版本和身份协议版本。
- Minecraft、Forge、AE2 版本。
- 语言、生成时间、模组清单及资源包顺序信息。
- 精确资源 ID、注册 ID、名称、图集坐标。
- 图集文件及哈希。
- 导出数量、失败数量和覆盖来源。

管理员将包放入服务端配置指定位置，启动时加载：

- 校验版本、文件大小、解压后大小、图片尺寸、哈希和路径。
- 防止路径穿越和压缩包异常膨胀。
- 不直接开放任意文件目录。
- 加载失败时保留基础名称和占位图，不影响库存监测。
- 第一版更新资源包后重启生效，不实现网页上传或文件热加载。

### 4. 前端 MVVM

采用 Vue 的明确 MVVM 分层：

- Model：API 数据、资源身份、精确数值和本地偏好。
- ViewModel：网络选择、查询条件、收藏、对比项、加载与错误状态。
- View：表格、筛选器、图表和对话框。
- 图表组件只消费 ViewModel 数据，不自行请求 API。
- 不把全部状态和业务规则塞进一个页面组件，也不为每个一次性操作制造抽象层。

### 5. 页面布局

```text
网络选择                    在线状态／最后采样时间       设置
搜索物品        类型筛选       NBT 合并       仅收藏

时间范围                  数据粒度                 数量／净速率

库存列表                                      趋势面板
★ 图标 名称      数量      净变化      净速率     选中项及对比图例
  收藏项置顶                                   主曲线
  普通条目                                     时间／数量／波动范围
                                               变体与网络事件
```

- 左侧库存表，右侧详情及趋势；桌面比例约 55:45。
- 收藏直接置顶，避免重复铺一整组装饰卡片。
- 点击行查看详情，复选框加入对比。
- 物品和流体混选时按单位分图，不使用容易误导的双 Y 轴。
- 小屏改为列表与详情切换，不强行塞入两栏。
- 大列表使用虚拟滚动，图标延迟加载。
- 页面不可见时暂停轮询；恢复后重新获取最新快照。
- 默认每 10 秒刷新，与采样周期一致。

### 6. 时间与筛选

时间范围提供：

`1m / 5m / 10m / 30m / 1h / 4h / 8h / 12h / 1d / 2d / 3d / 7d / 30d`，以及自定义范围。

数据粒度独立提供：

`自动 / 10s / 1m / 5m / 10m / 15m / 30m / 1h / 4h / 8h / 12h / 1d / 2d / 3d / 7d`。

按留存精度和点数限制禁用不可用组合，并说明原因。不能把 15 分钟历史插值伪装成 10 秒历史。

筛选支持：

- 名称及注册 ID 搜索。
- 物品／流体／其他。
- Mod 命名空间。
- 仅收藏。
- 是否显示当前为零但仍有历史的条目。
- 精确／合并模式。

第一版不加入外部通知、预测补货、配方分析或实际生产／消耗追踪。

### 7. 视觉规范与本地设置

基础色板：

| 用途     | 色值      |
| -------- | --------- |
| 页面背景 | `#18212B` |
| 工作面板 | `#202C38` |
| 分隔线   | `#354555` |
| 主文字   | `#E6EDF3` |
| 次文字   | `#A3B2C0` |
| 操作强调 | `#D8AA62` |

数字使用等宽数字特性，保持数量列对齐；正文使用清晰的中文系统无衬线字体。图表通过颜色、正负号和线型共同区分变化，不能只靠红绿。

不使用宣传首页、巨大欢迎标题、渐变装饰、玻璃拟态或反复出现的解释文案。必要说明放在工具提示中。

本地设置以“站点＋API 路径＋存档 UUID”隔离，网络偏好进一步按网络 UUID 隔离：

- 收藏和顺序。
- 网络别名。
- 筛选、排序、时间范围和粒度。
- 合并模式。
- 对比项、面板宽度和单位偏好。

精确变体收藏与合并组收藏分开保存，切换模式不得偷偷转换或丢失收藏。浏览器存储失败时退化为当前会话内存状态，并显示一次简短提示。

## 五、实施顺序、测试与交付标准

### 1. 实施顺序

1. **建立工程和协议**
   创建独立项目、共享身份模块和构建配置；提取客户端工具，保留来源与许可证；先验证两侧身份一致。

2. **完成采集原型**
   在本地 Forge 测试环境验证控制器网络发现、库存读取、线程边界、断电和重组；此阶段不连接真实服务器测试。

3. **完成 SQLite 历史引擎**
   实现变化点、覆盖记录、基线、降采样、容量管理、故障恢复及时间查询。

4. **完成只读 HTTP 和认证**
   实现接口契约、认证、限流、查询边界、静态网页分发和生命周期处理。

5. **完成客户端资源工具**
   名称、真实图标渲染、变体补采集、资源包校验和服务端加载。

6. **完成前端**
   先验证库存列表与趋势操作，再补齐收藏、筛选、NBT 合并、多项对比和移动端。

7. **集成与性能验证**
   在匹配整合包的本地隔离环境验证，产出正式重映射 JAR、测试记录和部署说明。

### 2. 必须覆盖的自动测试

**身份与统计**

- NBT 键顺序变化不改变身份；类型、列表顺序及有效内容变化会改变身份。
- 数量超过 `2^53` 仍能精确传输和显示。
- 合并结果超过 `long` 范围时不溢出。
- 两个变体此消彼长、合计不变时，合并曲线保持不变。
- 新资源、归零、重新出现、时间不均匀、缺口、重启和拓扑切换。
- 流体 mB／B 换算及单位分图。

**SQLite**

- 长期不变资源可正确还原平直曲线。
- 删除历史后边界基线仍正确。
- 降采样保留首尾和极值，重复执行不产生重复记录。
- 崩溃后未提交事务不污染结果。
- 文件大小限制、磁盘满、WAL 无法回收、读取超时和队列满。
- 保留期跨越、提前清理及字典记录回收。
- 未知版本和数据库损坏不触发覆盖。

**网络与安全**

- 多控制器去重、跨维度网络、无控制器排除。
- 重启恢复身份、拆分、合并、全部控制器更换、卸载及断电。
- 匿名、错误密码、公开模式、会话超时和密码变更。
- 未授权用户不能读取库存、历史或资源映射。
- 不存在游戏写入和上传接口。
- 路径穿越、非法参数、恶意名称、超大请求和资源包异常。

**浏览器与导出器**

- 快速切换网络时旧响应不能覆盖新页面。
- 本地收藏隔离、合并模式切换、存储失败和资源包更新。
- 空网络、零库存、只有一个样本、离线及历史暂停状态。
- 多选上限、单位分图、超大数字和缺口显示。
- 导出取消、资源重载、单项渲染失败、状态恢复及文件发布完整性。

### 3. 性能验收

使用可复现合成数据，至少覆盖：

- 10 个网络，每个 10,000 个精确资源。
- 大量恒定资源和高变化率资源两种负载。
- 20 个并发网页会话。
- 加速生成 30 天数据，验证容量管理。
- 最多 6 条、每条最多 1200 桶的趋势查询。

验收关注：

- 网页并发不会增加 AE 采样次数。
- 主线程无数据库、文件和网络等待。
- 采样、序列化、写入和查询耗时分别记录。
- 默认负载下，采样额外耗时以平均低于 1 ms/tick、采样 tick 的 P95 低于 5 ms 为优化目标；报告机器和样本条件。
- 不把“检查时间预算”宣称为能中断一次昂贵的 AE 原生读取。
- 内存、队列和磁盘占用不随运行时间无限增长。
- 历史查询超时能取消，不妨碍持续采集。
- 容量不足时行为与文档一致，不破坏已有历史。

这些是验证目标，不能在没有测试结果时报告为已达成。

### 4. 真实整合包验收

本地隔离环境使用匹配版本，验证：

- AE2 普通存储、流体存储。
- 存储总线连接外部库存。
- Mega Cells、ExtendedAE 相关存储和控制器。
- NBT 不同的附魔物品、药水、自定义名称和耐久物品。
- 客户端生成的中文名称及图标与游戏实际显示相符。
- 未安装客户端导出器的普通玩家能正常加入服务器。
- 与现有 AE2 Web Integration 共存，无端口、Mod ID 或依赖冲突。

前端截图至少检查 1440px、1024px、390px 宽度，以及键盘焦点、文字截断、长名称、大数字和缺失图标。

### 5. 最终交付

- 可安装的服务端发行 JAR。
- 单独的客户端资源导出器发行 JAR。
- 完整源码、构建 Wrapper、lockfile、许可证和来源记录。
- API、身份及资源包协议说明。
- SQLite 保留、清理、备份和恢复说明。
- Windows 构建及 Ubuntu 部署说明。
- HTTPS 反向代理示例。
- 明确区分自动测试、本地整合包测试和实际服务器测试的验证报告。
- 安装、停用、卸载及保留历史文件的操作说明。

构建必须验证正式 JAR 的重映射、Java 17 字节码、Forge 元数据，以及服务端 JAR 不包含或加载客户端渲染代码。不能把开发 JAR 当安装包。

执行阶段先在新项目中保存本计划及验收清单，再逐项落实。完成开发不代表自动获准修改线上配置、开放端口、替换 Mod 或重启服务器；线上部署另行进行。
