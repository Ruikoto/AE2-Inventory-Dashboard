`gradle build` 成功。Java 自动测试 32 项通过，0 失败、0 跳过：contracts 5 项，服务端原生无关测试 23 项，原生 NBT 测试 2 项，客户端资源打包 2 项。前端 Vitest 6 项和 Playwright 5 项通过；格式检查、TypeScript 编译及生产网页构建通过。

发行检查验证两个安装包含 Forge 元数据、class major version 不高于 61，执行正式重映射。服务端包含生产网页、单个 SQLite Forge Jar-in-Jar，不包含导出器、Minecraft 客户端渲染类或展开的 org.sqlite 类。内嵌驱动 SHA-256 固定为现场相同版本。

测试在 Windows 沙箱中运行浏览器断言后曾卡在 Vite 子进程回收；清理本项目进程后，以普通本地进程重跑，5 项全部通过且正常退出。Java ZIP 文件系统在沙箱内只读，构建使用普通本地进程。这些环境限制不以跳过测试处理。

## 原生 Forge 隔离环境

Java 17.0.20.1；Minecraft 1.20.1；Forge 47.4.16。AE2 使用与服务器相同 SHA-256 的正式 15.4.10 运行 JAR，开发 Maven JAR 不用于原生启动。游戏和 RCON 仅监听本机，使用独立合成世界，无名称/图标资源包。

已执行：

- 空网络和正常物品/流体库存采集；NBT 铁锭两变体分别为 9007199254740993 和 321，合计 9007199254741314；水 123456 mB。
- 多控制器网络发现、无控制器网络排除、冲突、拆分/合并、断电与恢复、完整快照归零。断电不产生零库存。
- 重启后保留两个活动网络 UUID；已合并的旧身份继续保持 merged，没有重新抢占控制器。
- 与现场 ExtendedAE 1.4.14、ExtendedAE Plus 1.5.3-fix、MEGA Cells 2.4.6、Omni Cells 1.1.1、旧 AE2 Web Integration 1.2.0-pre 及必要依赖一起启动；现有 SQLite Mod 与内嵌驱动共存。另一次启动移除外置 SQLite Mod，内嵌驱动可独立工作。
- MEGA Cells 存储的金锭 777、Omni Cell 独立 SavedData 中的钻石 888、存储总线连接箱子的铜锭 64 均被读取。网络样板控制器没有被当成 ME 控制器。

- 管理员本地身份清单导出成功；测试服正常保存并停止。

该环境只加载相关 AE Mod，未加载全部约 307 个整合包 Mod、KubeJS 脚本或真实世界。缺失可选 Mod 时附属 Mod 有配方/战利品和 mixin 警告；Forge 在线版本检查有超时，均不归为本项目的干净全整合包验收。大整数库存单元 NBT 是刻意超出普通单元容量的边界测试，不模拟生存玩法。

## 性能场景

本机 Windows 11，AMD Ryzen 7 9800X3D；测试进程可见 8 个逻辑处理器，约 31.38 GiB 内存，Java 17，Node 24.14.0。数据库合成工作负载的 Java 堆上限 1 GiB；测试过程中存在其他本地开发进程，不是独占性能基准。以下均为一次运行的观测值，不作为 SLA。

| 工作负载 | 结果 |
|---|---|
| 10 网络 × 10000 精确资源，含各自分组 | 快照构造一次约 14.93 ms；十网络不变采样写入约 143.28 ms；十网络全部变化写入约 10.25 s；正常关闭后约 147.64 MiB |
| 六条各 1200 个显示点 | 查询约 46.36 ms，确认为 6 × 1200 点；20 个直接并发存储调用完成 16 个，其余被有界读连接拒绝，无无界等待 |
| 30 天，259200 次十秒采样，一精确序列加一分组 | 实际约 445 s；正常关闭后 7266304 字节（约 6.93 MiB）；30 天自动粒度一小时、721 点；查询约 28.37 ms |
| 20 个直接并发查询，长期数据库 | 20 个成功，总计约 22.83 ms |
| 16 MiB 目录预算、120 精确资源、700 次变化采样 | 容量压力自动测试通过；每次检测实际目录占用不超预算，允许清理或整份拒绝 |

复现：`:server:performanceTest -Pworkload=large`、`long`、`dense`。三种场景独立运行；没有把十万个资源全量变化连续模拟三十天。后台高变更写入耗时可能导致有界队列丢样，网页显示缺口；不以阻塞游戏解决。

没有测量真实 AE 原生采样 tick 的平均值/P95，不能报告已达到平均 <1 ms/tick、采样 tick P95 <5 ms 的优化目标。纯 Java 快照构造耗时也不等于完整主线程采样耗时。
