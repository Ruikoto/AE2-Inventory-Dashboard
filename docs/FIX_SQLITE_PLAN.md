# SQLite 取消隔离修复计划

2026-10-21，针对已部署 0.1.0-dev 的 SQLITE_INTERRUPT 与事务状态错误。

## 根因和边界

固定版本 SQLite Forge adapter 3.36.0.3+20211227 的 ProgressHandler 存在跨连接串扰，已在 Windows/Linux 内存数据库复现。继续保留该运行依赖以兼容整合包，不修改第三方 Mod、不升级现场驱动、不读取或复制真实库存。setQueryTimeout 在此版本仅设置 busy timeout，不能用作执行时间限制。

## 实现

1. 移除服务端所有 ProgressHandler。使用单个有界生命周期的定时执行器，直接对操作绑定连接的 native DB 调用 interrupt；读查询保持 3 秒墙钟上限，Java 重建循环也检查同一截止时间。
2. 操作结束与取消回调同步关闭，先撤销取消再关闭连接。旧任务不能影响下一次写操作。读连接仍最多两个，不阻塞游戏主线程。
3. 写事务失败后停止该操作的取消任务、关闭异常连接以回滚未提交数据，清除差分基线，使用同一个数据库文件重新建立连接；不吞异常，不删除历史。重连失败则保留暂停状态，后续采样可重试。
4. 写操作继续检查线程中断和空间预算；定时检测加预留空间，保持目录容量压力测试。维护补充资源引用索引与覆盖段索引，避免相关扫描退化。
5. 首次 schema 检查仍保护较新/损坏数据库；索引采用幂等添加，schema v1 的数据格式不变。
6. 版本变为 0.1.1-dev。更新说明、安装包与哈希；提交推送后替换服务器 Mod，备份旧 JAR 到 mods 以外。服务器由用户手动重启，在线数据库和配置不改动。

## 验证

- 独立连接读查询超时/线程取消不会中断写入；取消任务关闭后不误伤后续操作。
- SQLite 自动回滚的故障事务后，后续写入、网络元数据和历史可恢复，没有半份样本或跨缺口速率。
- 至少 4000 条资源目录，完成读查询后超过旧回调三秒期限，跨多轮维护继续采样。
- 全部 Java 检查及容量压力测试；相同旧驱动在 Windows/Linux 的多连接取消测试。
- 正式 Forge JAR 与现场附属 Mod 共存；大目录持续轮询跨多轮一分钟维护，检查错误、当前/历史时间和丢样。
- 上传不等于线上已生效，保持用户手动重启边界。
